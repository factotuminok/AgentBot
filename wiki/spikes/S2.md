# S2 — DevForge's agent host in a separate container

**Verdict: PASS.** The host ran unchanged: DevForge files copied byte-for-byte, no source patches. A plan-profile run ended with `yield`, `web_search` returned results, and the session loaded the skill from the downloaded skills directory. To keep every omp write inside the run directory, the worker has to set the environment (see §Required changes).

## Question

Does DevForge's agent host (`src/agent/host.ts` → `serve.ts` → `session.ts` and their imports) run unchanged in a separate container, with `Settings.init` once per process, a run-local auth store and a downloaded skills directory?

## What was built

`spikes/s2/` (removed from podman afterwards; the sources stay):

- `app/src/` holds files copied verbatim from DevForge `64ba5ca`: `agent/{host,serve,session,tools,todos,oom,reap,loadout,scratchTools,protocol,prompts,ui,runner,ompAssets}.ts`, `log.ts`, `usage.ts`, `ompconfig.ts` and `engine/scratch.ts`. The host loads only these at runtime: `host`, `serve`, `session`, `ui`, `protocol`, `loadout`, `oom`, `todos`, `tools`, `scratchTools`, plus `../log`, `../usage`, `../ompconfig` and `../engine/scratch`. Its `../agentlog` imports are type-only and erased by Bun. `runner.ts`, `ompAssets.ts`, `reap.ts` and `prompts.ts` belong to the main process; the host doesn't load them.
- `app/driver.ts` stands in for `runner.ts`. It runs `Bun.spawn([bun, src/agent/host.ts], { serialization: "json", detached: true, ipc })`, sends one hand-built `start` message, answers `session_file` with `ok` and refuses `ui`/`tool_call`, and prints every child message.
- `app/package.json` installs `@oh-my-pi/pi-coding-agent` 18.12.1, `@oh-my-pi/pi-utils` 18.12.1 and `zod` ^4.6.7.
- `Containerfile` uses `docker.io/oven/bun:1.4.2-debian`, adds `git ca-certificates procps`, runs `bun install`, and runs as user `bun` (uid 1000) with `HOME=/agentrun/home`. The image was 1.29 GB.
- `setup-and-run.sh` runs inside the container. It creates a throwaway git repo at `/agentrun/repo` (`README.md` titled `# S2 Probe Repo`) and the "downloaded" skill `/opt/downloaded/omp/skills/s2-probe/SKILL.md`, then execs the driver.

The `start` message:

- `runtime = { agentDir: "/agentrun/omp-agent", ompDir: "/opt/downloaded/omp", providerKeys: {} }`
- `opts`: `profile: "plan"`, `modelPattern: "anthropic/claude-haiku-4-5"`, `thinking: "low"`, `cwd: /agentrun/repo`, `sessionDir: /agentrun/sessions`, a 3-field `outputSchema`, `limits {5 min, $0.50}`, `wantLoadout: true`

### Credentials

The run used the user's omp Anthropic OAuth sign-in. Expiry was checked before each run without reading any token: 466 → 462 minutes left; omp's refresh skew is 60 s (`OAUTH_REFRESH_SKEW_MS`).

1. `sqlite3 -readonly ~/.omp/agent/agent.db ".backup"` copied the store into a `mktemp -d` dir under `/var/folders/…` (shared with the podman machine by virtiofs).
2. In the copy, every credential except `anthropic` was deleted, together with leases, blocks, cache and usage rows, and the file was `VACUUM`ed.
3. The copy was bind-mounted at `/agentrun/omp-agent`; it was never `COPY`ed into the image.

After both runs, the credential row's SHA-256 in the copy matched the original, and `auth_credential_refresh_leases` was empty, so no refresh happened. The temp dir, both containers and the image were deleted afterwards. The pulled base image `oven/bun:1.4.2-debian` was left in place for other spikes.

## Findings

- **`Settings.init` once per process holds.** `initRunSettings` (`Settings.init({ inMemory: true, agentDir, cwd: agentDir, overrides })`) ran once per host process without throwing, so nothing in `openSessionRuntime` or `ModelRegistry` initializes settings earlier. With the global settings in place, `web_search` worked (D-064).
- **The run-local auth store works.** `discoverAuthStorage(agentDir)` plus `new ModelRegistry(authStorage, <agentDir>/models.yml)` resolved `anthropic/claude-haiku-4-5` from a single-credential `agent.db` in a writable directory.
- **The downloaded skills root works.** `disableExtensionDiscovery: true` plus `additionalExtensionPaths: [ompDir]` loaded `skills/<name>/SKILL.md` from an arbitrary path (`/opt/downloaded/omp`), with source `omp-plugins:user`. The loadout's agent discovery (`discoverAgents(..., { explicit: [ompDir], mode: "explicit-only" })`) only runs when the `task` tool is active, so the plan profile didn't exercise it.

## Required changes for phase 3

**No source patch was needed to run outside the shared data directory.** Phase 3 must still change the following.

### Environment and paths (worker)

1. **Set `PI_CODING_AGENT_DIR` to the run's `agentDir`** in the host's environment. Without it, omp writes `custom-session-files/` to `$HOME/.omp/agent`, ignoring the `agentDir` the session was given. DevForge got this from its Dockerfile `ENV PI_CODING_AGENT_DIR=/data/omp-agent`.
2. **Point `HOME` at a writable run-local directory.** omp always writes `$HOME/.omp/install-id` and `$HOME/.omp/logs/`. DevForge used `HOME=/data/home`.
3. **Make `agentDir` a writable directory, not a read-only file mount.** omp opens `agent.db` read-write (WAL/SHM files) and creates `models.db` (about 7.8 MB, rebuilt each run with network fetches and about 1.1 s) and `skill-descriptions.db`. On memory-backed run-local storage (architecture §5), budget about 8 MB for this. Alternatively, ship the orchestrator's model cache in the run spec or skills bundle, or put `models.db` somewhere other than the auth tmpfs.
4. **Writable paths are enough.** The host needs no writable path outside the run directory, the skills directory and `/tmp`; a read-only root filesystem works (run 2).

### Auth (CRED-02/03)

5. **Seed the run-private store as an omp `agent.db`.** `openSessionRuntime` calls `discoverAuthStorage(agentDir)`, which reads `<agentDir>/agent.db`; the spike seeded it with a SQLite copy. The worker has to write the run-spec snapshot in that format, or `openSessionRuntime` has to switch to whatever store S1 produces.
6. **Stop the host from refreshing tokens itself.** omp refreshes a token within 60 s of expiry inside the host. That breaks CRED-03 unless S1's refresh hook replaces `discoverAuthStorage` in `openSessionRuntime`.

### Layout and imports

7. **Carry `UPLOAD_LIMIT_BYTES` along.** `session.ts` → `scratchTools.ts` imports it from `../engine/scratch` at runtime, so the worker's file set must include it (or the constant moves to `src/shared`).
8. **Make the `TranscriptEvent` type available for typecheck.** `../agentlog` is a type-only import (erased at runtime), but typecheck needs the type.

### Renames and wording (not needed to run)

9. `reap.ts` `AGENT_RUN_ENV = "DEVFORGE_AGENT_RUN"` → `AGENTBOT_AGENT_RUN`.
10. `ompAssets.ts` `DEVFORGE_OMP_DIR` (main-process side only).
11. "DevForge … Discord thread" in `todos.ts` `TODO_INSTRUCTION`.
12. "DevForge" in `session.ts` `oomSteer`.
13. The reasons in `ompconfig.ts` `LOCKED_SETTINGS`, and `connectMcp`'s `provider: "devforge"`.

### `web_search` provider

14. With no search keys, omp's automatic chain uses Parallel's keyless public endpoint. Workers therefore need outbound HTTPS to `search.parallel.ai` unless admins configure another provider.
