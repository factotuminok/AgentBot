# S4 — code-server lock-down

**Verdict: PASS, with gaps for WEB-30.** With the final configuration (below), all three attempts failed and each one was logged: opening a terminal (keybindings, command palette, quick access, menu, panel), running a task (palette, menu, `task` quick access, `runOn: folderOpen`, user tasks) and installing an extension (Marketplace view, Install from VSIX, Install Extension from Location, `code-server --install-extension`). No shell process started. The first configuration, which followed WEB-31 literally, failed: an automatic task ran. Four changes fixed it (§Findings 1–4), and the requirement text has to change to match (§Consequences). An admin who sets out to get a shell can still get one: they disable the lock-down extension, then add a terminal profile to the workspace `.vscode/settings.json` (§Gaps 1–2). That is the admin-level power WEB-30 already accepts.

Plan's "Pass when": *All three attempts fail and are logged.* Observed in the final run: 9 terminal attempts → 8 `blocked` + 1 `terminal-closed` log lines. 9 task attempts → 3 `blocked` + 6 `terminal-closed`/`task-terminated`, and no `/tmp/pwned-*` file. The automatic task did not run and showed no prompt. Marketplace searches were empty, the two install commands logged `blocked`, and every CLI install exited 1. The Focus / Select Default Profile / Attach to Session rows in the table come from the previous run, whose image differed only in `/etc/shells`, the location-install shadow and `--enable-remote-storage`.

## Question

Can code-server be locked down so that the marketplace is off, built-in extensions other than JSON/YAML/Markdown are gone, a bundled extension closes the integrated terminal, `SHELL` and the login shell are `/usr/sbin/nologin`, and settings turn off automatic tasks and workspace-trust prompts (WEB-14, WEB-30, WEB-31; architecture §2.5, §7.1)?

## What was built

All under `spikes/s4/`. The image and container `agentbot-spike-s4` were removed afterwards.

- `Containerfile`: `debian:bookworm-slim` + `ca-certificates curl procps`. It installs the code-server **4.143.1** release tarball (Code 1.143.1, commit `22ddf60`, released 2026-10-23; 4.144.0 came out on the day of the spike and was skipped) under `/opt`, the way DevForge does. In the same layer it deletes every built-in extension except `json json-language-features yaml markdown-basics markdown-language-features theme-defaults theme-seti`. It creates `agentbot` 10001:10001 with login shell `/usr/sbin/nologin`, writes `/etc/shells` = `/usr/sbin/nologin` only, and installs the bundled `.vsix` at build time into the root-owned `/opt/agentbot/vscode-extensions`.
- `vscode/settings.json`, `vscode/tasks.json`: the locked settings and an empty user task list, in the image, root-owned.
- `start.sh`: stands in for `agentbot web` starting code-server: env, symlinks, flags (§Consequences). It has spike-only switches: `S4_NOEXT=1` uses an empty extensions dir, to test layer 2 alone; `S4_TRUST=1` turns workspace trust on; `S4_GALLERY` overrides the gallery.
- `fwd.js`: a spike-only TCP forwarder from `0.0.0.0:13338` to `127.0.0.1:13337`. code-server itself stays on loopback, and podman publishes 13338 on host loopback only.
- `ext/`: the lock-down extension (`package.json`, `extension.js`, plain JS), packaged to `agentbot-lockdown.vsix` with `bunx @vscode/vsce package --allow-missing-repository --skip-license --allow-star-activation`. It:
  - shadows commands by registering the same ids: a fixed list plus every `workbench.action.(terminal|tasks).*` id from `getCommands()`, 184 in all. It re-registers them every 5 s (§Findings 2). Each call logs `blocked` and shows "AgentBot: <id> is disabled in this editor.";
  - binds ctrl+`` ` ``, ctrl+shift+`` ` `` and ctrl+shift+c to its own `agentbot.terminalDisabled`;
  - disposes every terminal in `window.terminals` and on `onDidOpenTerminal`, terminates each task on `tasks.onDidStartTask`, and stops debug sessions;
  - logs one JSON line per event to `~/agentbot-lockdown.log` and to a LogOutputChannel.
- Workspace fixture `home/workspace/` (`settings.json`, `README.md`, `notes.yaml`, `.vscode/settings.json`). Test `tasks.json` files were written into the container with `podman exec`, which stands in for a save.
- The UI was driven with headless Chromium. A 50 ms `ps` poller inside the container recorded every new process.

## Findings that changed the configuration

1. **Application-scoped settings are ignored in `Machine/settings.json`.** The first run used Machine settings only, as WEB-31 says. The settings editor greyed out `task.allowAutomaticTasks`, `security.workspace.trust.*`, `extensions.allowed`, `extensions.autoUpdate`, `extensions.autoCheckUpdates` and `telemetry.telemetryLevel` (they are `scope: application`). On reload VS Code showed "This workspace has tasks (s4-auto) defined … Do you want to allow automatic tasks to run …? Allow / Disallow". After **Allow**, the task wrote `uid=10001(agentbot) …` to `/tmp/pwned-auto`, although the extension closed its terminal 3 ms later (`terminal-closed` 01:15:42.712). Fix: the same settings in `User/settings.json` as well. With that, there was no prompt and no run.
2. **Command shadowing depends on registration order.** The workbench runs a command's latest registration. Terminal commands are registered before extensions activate, so the shadows won. The Extensions view registers its actions when it is first opened, so the first "Install from VSIX…" opened the real file picker. Fix: re-register the shadows every 5 s. After that the attempt logged `blocked`.
3. **VS Code offers every shell in `/etc/shells` as a terminal profile.** `SHELL` and nulled `bash`/`sh` profiles don't hide them. "Select Default Profile" listed `bash (2) /usr/bin/bash`, `dash`, `dash (2)`, `rbash`, `rbash (2)`, `sh (2)`. With the extension disabled, "Create New Terminal (With Profile)" › `dash` gave a working shell (`/tmp/pwned-dash`, `/bin/dash` child of ptyHost). Fix: `/etc/shells` holds only `/usr/sbin/nologin`. After that the list showed only `nologin /usr/sbin/nologin`, and a terminal showed "The terminal process "/usr/sbin/nologin" failed to launch (exit code: 1)."
4. **The marketplace needs `EXTENSIONS_GALLERY='{}'`.** code-server uses open-vsx when the variable is unset or empty (`process.env.EXTENSIONS_GALLERY ? JSON.parse(…) : product.extensionsGallery || {open-vsx}`). It applies only to processes that have it: `code-server --install-extension redhat.vscode-yaml` without it installed v2.0.0 from open-vsx into the default extensions dir. The final configuration has two more locks: `extensions.allowed` in read-only user settings, and a root-owned extensions dir.
5. code-server 4.143.1 has **no `--disable-extension`** (its CLI parser throws `Unknown option`), so built-ins are deleted in the image instead (§Consequences).
6. On start, VS Code rewrites `"extensions.autoUpdate": false` as `"off"`. With read-only settings the write fails and shows "Failed to save 'settings.json' … EACCES" toasts. Fix: write `"off"`.
7. **Web extensions install from any https URL.** Developer: Install Extension from Location… works because code-server's CSP has `connect-src 'self' ws: wss: https:`. It installed a test web extension into browser storage ("Browser - Installed"). `extensions.allowed` kept it disabled ("Some extensions are disabled because they are configured not to be allowed"), and its `ext.js` was never fetched. The command is now shadowed too.

## Gaps (record in WEB-30)

1. **The admin can disable the lock-down extension** (Extensions view › gear › Disable, then reload). Layer 1 is then gone until the state is reset. With `--enable-remote-storage` the disabled list is stored on the server, in `~/.local/share/code-server/User/globalStorage/state.vscdb` under key `extensionsIdentifiers/disabled` (observed: `[{"id":"github.copilot-chat"},{"id":"agentbot.agentbot-lockdown"}]`). The web process can delete that file before each code-server start. Not tested.
2. **Workspace settings can define a terminal profile.** Workspace trust is disabled, so restricted settings in `.vscode/settings.json` apply. With the extension disabled, `{"terminal.integrated.profiles.linux":{"evil":{"path":"/bin/dash"}},"terminal.integrated.defaultProfile.linux":"evil"}` + Create New Terminal gave a dash shell (`/tmp/pwned-wsprofile`). So layer 2 holds only while nobody edits workspace settings. Phase 7 should have the web process own `.vscode/settings.json`: rewrite it from the orchestrator's version and reject local edits. The admin can still open any file under `$HOME` with File › Open File (its dialog browses the whole filesystem). Because the `User/` dir is agentbot-writable, replacing the settings symlink is possible in principle (not tested).
3. **Closing on `onDidOpenTerminal` is a race, not a gate.** Finding 1 shows a short task finishing before the close. In the final runs, 10 manual task runs were all stopped before they wrote anything. Tasks stay safe only while nothing runs them: no workspace `tasks.json` (WEB-31 layer 3), read-only user tasks, automatic tasks off.
4. An extension cannot remove palette entries, menu items or the Terminal tab of the panel. They stay visible and lead to the "disabled" toast. Toggle Panel opens on the Terminal tab, which creates a terminal; the extension closes it, and the panel hides again (height 0) because its last terminal closed. WEB-28 needs the Problems panel, so phase 7 must check that it opens (View › Problems); not tested here.
5. The extension host runs `/bin/sh -c ls -l /proc/[0-9]*/fd/[0-9]* | grep socket:` about every 30 s (VS Code's port detection), even with `remote.autoForwardPorts: false`. nologin cannot stop VS Code or extensions from starting programs through `/bin/sh`.
6. Log noise: on every extension-host start, code-server logs "resolving shell environment failed Unable to resolve your shell environment: Unexpected exit code from spawned shell (code 1, signal null)". This is expected with nologin. VS Code's `--force-disable-user-env` is rejected by code-server's CLI; `VSCODE_CLI=1` skips the step in the VS Code source but was not tested.
7. Cosmetic: the browser still requests snippet files of the deleted built-ins (42 console errors such as `static/extensions/swift/snippets/swift.code-snippets`). The workspace's `settings.json` opens in "JSON with Comments" mode (VS Code's own association for that file name).
8. Workspace trust as an extra gate (`S4_TRUST=1`, no lock-down extension): the workspace opens in Restricted Mode with no prompt. `task` quick access listed no tasks. Creating a terminal or running a task asked "Do you trust the authors of the files in this folder?"; **Cancel** left nothing running. The automatic task did not run. One click on "Trust Folder & Continue" unlocks everything, so this is a speed bump, not a layer. Its effect on WEB-25's JSON-schema mapping in `.vscode/settings.json` was not tested. The final configuration keeps trust off, as WEB-31 says.

## Consequences for phase 7

**Image (§7.1)**, in the code-server install layer:

```sh
cd /opt/code-server/lib/vscode/extensions && for d in */; do
  case "${d%/}" in json|json-language-features|yaml|markdown-basics|markdown-language-features|theme-defaults|theme-seti) ;;
  *) rm -rf "$d" ;; esac; done
useradd --uid 10001 --gid 10001 --shell /usr/sbin/nologin agentbot
printf '/usr/sbin/nologin\n' > /etc/shells
code-server --user-data-dir /tmp/cs-build --extensions-dir /opt/agentbot/vscode-extensions \
  --install-extension /tmp/agentbot.vsix    # as root; dir stays root-owned 0755
```

Built-ins in 4.143.1: 95 extension dirs. Kept: the seven above; the two themes hold no code. Deleted, among others: `git git-base github github-authentication microsoft-authentication npm grunt gulp jake typescript-language-features ms-vscode.js-debug ms-vscode.js-debug-companion ms-vscode.vscode-js-profile-table debug-auto-launch debug-server-ready copilot` (GitHub Copilot Chat, 158 MB, with terminal contributions; `product.json` lists it in `builtInExtensionsEnabledWithAutoUpdates`) `terminal-suggest emmet merge-conflict configuration-editing extension-editing ipynb simple-browser tunnel-forwarding references-view search-result media-preview mermaid-markdown-features markdown-math php-language-features css/html-language-features`, the shared `node_modules/typescript`, and all grammar-only language and theme packs.

**Start** (web process, every start). Symlink the locked files from the image:

```sh
ln -sfn /opt/agentbot/vscode/settings.json ~/.local/share/code-server/User/settings.json
ln -sfn /opt/agentbot/vscode/settings.json ~/.local/share/code-server/Machine/settings.json
ln -sfn /opt/agentbot/vscode/tasks.json    ~/.local/share/code-server/User/tasks.json
```

Then start code-server:

```sh
EXTENSIONS_GALLERY='{}' SHELL=/usr/sbin/nologin code-server \
  --bind-addr 127.0.0.1:13337 --auth none \
  --extensions-dir /opt/agentbot/vscode-extensions \
  --disable-telemetry --disable-update-check --disable-getting-started-override \
  --disable-workspace-trust --disable-file-uploads --disable-proxy \
  --ignore-last-opened --enable-remote-storage <workspace>
```

`--enable-remote-storage` keeps workbench state (extension enablement included) on the server, where web can reset it (§Gaps 1).

**Settings** (`spikes/s4/vscode/settings.json`; must be in `User/`, see Finding 1):

```json
{
	"task.autoDetect": "off", "task.allowAutomaticTasks": "off", "task.problemMatchers.neverPrompt": true,
	"security.workspace.trust.enabled": false, "security.workspace.trust.startupPrompt": "never",
	"terminal.integrated.profiles.linux": { "bash": null, "sh": null, "tmux": null, "pwsh": null, "JavaScript Debug Terminal": null },
	"terminal.integrated.automationProfile.linux": { "path": "/usr/sbin/nologin" },
	"terminal.integrated.hideOnStartup": "always",
	"extensions.allowed": { "agentbot.agentbot-lockdown": true },
	"extensions.autoUpdate": "off", "extensions.autoCheckUpdates": false, "extensions.ignoreRecommendations": true,
	"remote.autoForwardPorts": false, "remote.restoreForwardedPorts": false,
	"chat.disableAIFeatures": true, "telemetry.telemetryLevel": "off", "workbench.startupEditor": "none"
}
```

`extensions.allowed` did not disable the kept built-ins: the JSON language server kept running.

**Extension manifest** (the AgentBot extension of WEB-28 takes these over): `"activationEvents": ["*"]`, `"extensionKind": ["workspace"]`, `"capabilities": {"untrustedWorkspaces": {"supported": true}}`. `contributes.keybindings` binds ctrl+`` ` ``, ctrl+shift+`` ` `` and ctrl+shift+c to a no-op command hidden from the palette (`menus.commandPalette` `"when": "false"`). `contributes.configurationDefaults` nulls the same terminal profiles. In code: shadow the fixed list (`spikes/s4/ext/extension.js` `SHADOWED`: terminal, tasks, debug start, `workbench.extensions.action.installVSIX`, `workbench.extensions.command.installFromVSIX`, `workbench.extensions.installExtension`, `workbench.extensions.action.installExtensionFromLocation`, disable-all, bisect, `terminal.focus`) plus every `workbench.action.(terminal|tasks).*` id, and re-register every 5 s. Dispose terminals on open, terminate tasks on start, stop debug sessions. Report each event to the web process (the spike wrote a file).

**Requirement text to change:**
- WEB-14: "MUST be installed at every start" → preinstalled at image build in a root-owned, read-only `--extensions-dir`, so nothing else can be installed or removed. It is still loaded at every start. The marketplace is off through `EXTENSIONS_GALLERY='{}'` and `extensions.allowed`. Built-ins are deleted from the image, since code-server has no `--disable-extension`.
- WEB-31 layer 2: add "`/etc/shells` lists only `/usr/sbin/nologin`".
- WEB-31 layer 3: "Machine-level settings" → "read-only user settings (`User/settings.json`, a symlink to a root-owned file; application-scoped settings are ignored at machine level), plus a read-only `User/tasks.json`".
- WEB-30: record §Gaps 1–3. The web process should also own `.vscode/settings.json` (§Gaps 2) and clear `User/globalStorage/state.vscdb` before starting code-server.

## Measurements

- Image: debian bookworm-slim 100 MB + apt layer 16.6 MB + code-server layer 406 MB = **523 MB**. code-server takes 397 MB on disk after pruning, against 642 MB for the unpacked tarball: removing the built-ins saves about 245 MB. Copilot Chat alone is 158 MB.
- Start-up: `podman run` → `/healthz` 200 in 332–346 ms. code-server logged "HTTP server listening" 75 ms after `exec`. The workbench rendered 193–768 ms after navigation, and the extension activated about 0.8 s after navigation. Installing the `.vsix` at start took 252 ms; it is now done at build time.
- Memory (`podman stats`): 67 MB idle with no client, of which the spike forwarder is about 50 MB RSS. 262 MB with one client and the JSON language server. 382 MB after a few minutes' session with several window reloads. That fits the web pod's 768 Mi request in architecture's resource table.

Cleanup: the container, the `agentbot-spike-s4` image and the pulled `debian:bookworm-slim` were removed, as were the temp files in `/tmp` and both local test servers.
