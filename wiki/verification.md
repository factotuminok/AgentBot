# Verification

Traceability from every requirement ID in [`requirements.md`](requirements.md) and [`architecture.md`](architecture.md) to the evidence that it holds, as of 2026-10-30 (phase 11). The status comes from reading the tests and confirming that they assert the behaviour; a test that only mentions an ID or runs the code path does not count. The suite was not run for this matrix. Recorded manual and e2e runs come from the phase notes in [`implementation.md`](implementation.md) §4 and the spikes in [`spikes/`](spikes/).

## Status values

| Status | Meaning |
|---|---|
| verified (automated) | Unit or integration tests assert every MUST clause, sub-bullets included. |
| verified (manual/e2e run recorded) | The clauses not covered by automated tests were observed in a recorded e2e, spike or manual run. |
| partial | Some clauses are asserted. The last column names the ones that are not. |
| not verified | No meaningful evidence. |
| needs real credentials | What remains can only be checked against a real Discord guild, GitHub App or Actions, or model. The notes say what the fakes cover. |
| withdrawn | The requirement is withdrawn or replaced. The notes name the replacement. |

Evidence notation: `` `file:line` "test name" `` points at the `test(...)` call. `impl §4 Phase N` is a phase note in `implementation.md`. `S1`–`S6` are spikes.

### Code that does not match the requirement text

These came up while classifying. Each needs a fix or a change to the requirement text.

- **GH-14** (resolved in phase 11): `review()` now calls `scheduler.stopJobs` before applying `pr_merged`/`pr_closed` (`test/integration/poller.test.ts:232,247`). Was: the requirement says to cancel queued jobs and abort the live session first, then move the issue to `done` or `cancelled`. `src/orchestrator/github/poller.ts:107-109` applies `pr_merged`/`pr_closed` first and calls `scheduler.cancelIssue` after.
- **DSC-22** (resolved in phase 11): the post-PR message now reads `CI fix pushed to PR #n (attempt n/max).` Was: after the PR is open, the fix_ci message is `✅ **CI fix pushed** to PR #n.` without "(attempt n/max)" (`src/orchestrator/discord/render.ts:340`). Only the pre-PR CI-gate message carries the count (`render.ts:347`).
- **ENG-05** (resolved in phase 11): `sweepSessions` now sweeps ended drafts too. Was: the start-up sweep `sweepSessions` (`src/orchestrator/store/sessions.ts:147`) sweeps ended issues and rejected plans, but not ended `/work issue` drafts.
- **WEB-06** (resolved in phase 11): the 308 carries all four headers; proxied responses get nosniff and same-origin and keep code-server's CSP/Cache-Control, an exemption now written into requirements.md WEB-06. Was: responses proxied from code-server under `/admin/vscode/`, and its 308 redirect, are built in `src/web/vscode.ts:233,259` without `SECURITY_HEADERS` (`src/web/http.ts:9`). The other web responses carry them. This is probably deliberate, since the CSP would break code-server, but the requirement says "every response".
- **OBS-01** (resolved in phase 11): every compose health check now probes every 30 s with timeout 5 s, start period 30 s and 3 retries (a shared `x-health` anchor), and the launcher gives each worker the same check, `agentbot health` (libpod `healthconfig`); `test/unit/composeFile.test.ts` and `test/integration/launcher.test.ts` assert both. Was: `compose.yaml` used `interval: 15s` and start periods of 60 s, 30 s and 20 s, and the launcher started workers without a health check.
- **JOB-07 / AGT-14** (resolved in phase 11): `maxCostUsdPerJob` was enforced on each agent run, so a job with CI fix runs could spend more than the limit in total. Following the name and JOB-04, it now bounds the job: each run gets what the job's earlier runs left (`runJobAgent`, `src/orchestrator/engine/jobs.ts`), and requirements.md JOB-07 and AGT-14 say so. Chat, `/work plan` and draft runs keep the full amount per run.
